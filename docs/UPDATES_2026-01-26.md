## Bug Fixes

### 1. Click Propagation on Delete Button
**Problem:** Clicking the delete button was triggering the parent row's click handler, causing the job to be selected and re-polled.

**User Report:** "lol clicking delete triggers re-processing"

**Solution:** Added `e.stopPropagation()` to all delete button click handlers to prevent event bubbling.

**Code Change:**
```tsx
<button
  onClick={(e) => {
    e.stopPropagation();
    setShowDeleteModal(true);
  }}
  // ...
>
```

---

### 2. Polling Bug After Delete
**Problem:** After deleting a job, the job count would decrease momentarily then bounce back up, requiring a manual page refresh.

**User Report:** "polling has a bug. click on delete number goes down one instantly then goes back up. then requires manual refresh"

**Root Cause:** When a job was deleted, the active job polling was still running. The polling `onSuccess` callback would re-add the deleted job back to the job history list before the refresh completed.

**Solution:**
- Added `onDeleteSuccess` callback to `JobRow` component
- In `onDeleteSuccess`, clear the active job first (stops polling) before refreshing the job list
- Removed the setTimeout delay that was causing race conditions

**Code Changes:**

In `JobHistoryTable`:
```tsx
onDeleteSuccess={() => {
  // Clear active job first to stop polling, then refresh
  if (activeJob?.jobId === job.jobId) {
    clearActiveJob();
  }
  refreshJobHistory();
}}
```

In `JobContext`:
```tsx
// Added clearActiveJob to context value
const clearActiveJob = useCallback(() => {
  setActiveJobId(null);
}, []);
```

---

### 3. TypeScript Error in JobContext
**Problem:** TypeScript error: `'oldJob' is possibly 'undefined'` in JobContext.tsx

**Solution:** Added null check before accessing oldJob properties:
```tsx
if (!oldJob) {
  return [job, ...prev];
}
```

### Download Button Fixes

**Problem:** Bank statement CSV download wasn't triggering - spinner showed but no file downloaded.

**Root Causes Found:**
1. Crypto download had wrong field name: expected `{ url }` but Lambda returns `{ downloadUrl }`
2. `window.open()` was getting blocked by popup blockers
3. Anchor element click doesn't work for cross-origin S3 URLs

**Solutions Applied:**

1. **Crypto Download Fix** (`app/dashboard/jobs/[jobId]/JobDetailClient.tsx`):
   ```tsx
   // Before (broken)
   const { url } = await response.json();

   // After (fixed)
   const { downloadUrl } = await response.json();
   ```

2. **Bank Download Fix** (`components/dashboard/BankPDFUploader.tsx`):
   ```tsx
   // Fetch file as blob to avoid popup blockers
   const fileResponse = await fetch(data.downloadUrl);
   const blob = await fileResponse.blob();

   // Create object URL and trigger download
   const blobUrl = window.URL.createObjectURL(blob);
   const link = document.createElement('a');
   link.href = blobUrl;
   link.download = `bank_${result.jobId}_${outputFormat}.csv`;
   document.body.appendChild(link);
   link.click();
   document.body.removeChild(link);
   window.URL.revokeObjectURL(blobUrl);
   ```

3. **Lambda Enhancement** (`backend/handlers/webhook.py`):
   - Added `ResponseContentType: "text/csv"` to presigned URL params
