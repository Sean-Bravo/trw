## Why Excel Format Matters

### The QBO Import Problem

QuickBooks Online is notoriously picky about imports:

❌ Wrong date format = "Unable to import"
❌ Text in Amount column = "Invalid data"
❌ Missing headers = "Unrecognized format"
❌ Extra columns = "Too many fields"

Our converter outputs the **exact format** QBO expects. No more import errors.

### The Xero Import Problem

Xero requires asterisks on required column headers:

```
*Date,*Amount,Payee,Description
01/15/2024,-1250.00,CHASE TRANSFER,Monthly rent
```

Miss that asterisk? Import fails silently with partial data.

We handle all these quirks automatically.

## Common Bank Statement Challenges (And How We Solve Them)

### Challenge 1: Wrapped Transaction Descriptions

**The Problem:**
```
01/15  AMAZON MKTPLACE PMTS
       AMZN.COM/BILL WA
       Card 1234
```

Three lines, one transaction. Most converters create three rows.

**Our Solution:**
We detect continuation lines (no date prefix) and merge them:
```
01/15/2024,"AMAZON MKTPLACE PMTS AMZN.COM/BILL WA Card 1234",-45.99
```

### Challenge 2: Separate Debit/Credit Columns

**The Problem:**
```
Date        Description      Debit      Credit
01/15/2024  Transfer Out     1,000.00
01/16/2024  Deposit                     2,500.00
```

**Our Solution:**
Single Amount column with proper signs:
```
01/15/2024,"Transfer Out",-1000.00
01/16/2024,"Deposit",2500.00
```

### Challenge 3: Inconsistent Date Formats

**The Problem:**
Same statement, multiple formats:
- Opening Balance: January 1, 2024
- Transaction: 01/15
- Closing Balance: 1/31/24

**Our Solution:**
All dates normalized to MM/DD/YYYY (or your preferred format).

### Challenge 4: Page Headers Repeated

**The Problem:**
Multi-page statements repeat headers:
```
Page 1 of 3
Account: ****1234
Date        Description        Amount
...transactions...
Page 2 of 3
Account: ****1234
Date        Description        Amount
...more transactions...
```

**Our Solution:**
Headers extracted once. Page markers stripped. Clean continuous data.
