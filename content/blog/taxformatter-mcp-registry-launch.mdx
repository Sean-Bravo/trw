## TaxFormatter Is Now a One-Line Install for Any AI Agent

If you're shipping an AI assistant that touches accounting, bookkeeping, or tax workflows, your agent probably has a "I can't reliably parse this CSV" problem. LLMs hallucinate transaction amounts when they try to read tabular data directly, especially across the dozen-plus formats in the wild from Coinbase, Binance, Kraken, Chase, Mercury, etc.

The MCP server fixes this. Three deterministic tools (`parse_crypto_csv`, `parse_bank_statement`, `list_supported_sources`), backed by the same parsing engine that powers the API, now installable in any MCP-compatible client:

```bash
npx -y @taxformatter/mcp-server
```

Configure once in your client's MCP settings, set `TAXFORMATTER_API_KEY`, and your agent gets verified structured data instead of a best-guess parse:

```json
{
  "mcpServers": {
    "taxformatter": {
      "command": "npx",
      "args": ["-y", "@taxformatter/mcp-server"],
      "env": {
        "TAXFORMATTER_API_KEY": "tf_live_your_key_here"
      }
    }
  }
}
```

Works in Claude Code, Cursor, Windsurf, and any other client that speaks the Model Context Protocol. Smithery also serves a hosted endpoint at `https://taxformatter--sean-bavo.run.tools` for clients that can't run `npx`.

For the deep dive on how the MCP server itself works — tool schemas, agent conversation patterns, edge cases — see the [original MCP server post](/blog/taxformatter-mcp-server-ai-agents). This post focuses on what's new.

## Tiered AI Insights on the Dashboard

When you upload a file in the dashboard, the parsed result now ships with an AI-written analysis alongside the cleaned transactions. The model used scales with your subscription tier.

| Tier | Model | What you get |
|------|-------|--------------|
| Free / Starter | Gemini 2.5 Flash | Fast summary covering totals, transaction-type breakdown, top assets, date range, taxable-event estimate, and data notes |
| Growth | Claude Sonnet 4.6 | Same coverage, with deeper reasoning on tax-relevant patterns and edge cases worth manual review |
| Business | Claude Opus 4.7 | Same coverage with the highest-quality reasoning Anthropic offers today — sharper on data anomalies and tax implications |

The output structure is identical across tiers — what changes is how carefully each model thinks about your data. Gemini Flash is fast and cheap and produces solid summaries on a small import. When there's real money involved, Sonnet and Opus pick up patterns Gemini misses (wash-sale-shaped activity, missing cost basis, suspicious gaps in date coverage, that kind of thing).

The deterministic stats (totals, transaction counts, date ranges) always render regardless of tier — those are computed in Python, not AI. The AI layer runs *on top* and degrades gracefully: if the model call fails, you still get the deterministic stats with an `ai_error` field explaining why.

**Heads up — dashboard only today.** AI insights are generated in the post-upload pipeline, which currently only runs for files dropped in the dashboard. The direct `/v1/parse` API call returns just the parsed transactions. Bringing insight generation into the API path is on the roadmap; if that gates an integration you're building, [tell us](mailto:support@taxformatter.com) and we'll prioritize it.

## What an Agent Conversation Looks Like

Concretely, here's what an AI agent does with the MCP server installed:

> **User:** I have a Coinbase export from 2024 — can you tell me how many sells I had in Q4 and what assets they were?
>
> **Agent:** *[calls `parse_crypto_csv` with the file path]*
>
> Your Coinbase export contains 247 transactions from January 12 through December 28, 2024. In Q4 specifically, you had 23 sell transactions: 14 BTC, 6 ETH, and 3 SOL, totaling roughly $12,450 in gross proceeds. Want me to filter for any specific asset or date range, or summarize the gain/loss profile based on Coinbase's reported cost basis?

The agent never touches the raw CSV. It receives clean, typed transaction objects from the parser and reasons about them in conversation. The same pattern works for `parse_bank_statement` against PDFs — Chase, Mercury, BoA, +10 more — with OCR, multi-page extraction, and date normalization handled by the engine instead of the model.

For a deeper dive on tool schemas, agent integration patterns, and the parsing engine's reliability story, see the [original MCP server post](/blog/taxformatter-mcp-server-ai-agents).
